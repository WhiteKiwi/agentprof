## Goal and observable boundary

A repeated explicit-root scan may continue one ordinary Claude source from its last committed complete LF boundary when authenticated bounded adapter state, the exact previous source bytes, current interpretation and the originally observed SQLite generation agree. The final stored events, turns, usage, relationships, diagnostics and capabilities must equal a fresh full replay of the same observed bytes. Pending calls, deferred results, replay suppression, provisional usage and unknown timing remain unchanged.

Checkpoint, source header, complete public contributions, whole-file equality proof and revision commit or roll back together. A crash must not expose an advanced checkpoint paired with older evidence. Restart reuses only the last committed generation. Interrupted reads and writes preserve the old generation; successful replay never duplicates contributions.

Claude checkpoint capture is optional and separately bounded by the existing 4 MiB adapter envelope cap. Unavailable capture does not reject a source that existing ingestion accepts. Historical or deliberately absent checkpoints remain a full-replay path; no one-time recapture requirement is imposed on unchanged cache hits merely to acquire a checkpoint. Codex remains full replay on changed sources and retains current verified unchanged-source reuse.

No CLI/report/output-shape change, cross-source reconciliation, copied-history inference, default-root expansion, new provider semantics, raw log persistence or performance/savings claim. Both public readiness flags remain false because broader provider/reconciliation acceptance remains open. The internally verified ordinary-Claude optimization is described precisely instead of promoting a global flag.

## Proposed safety contract

- Schema 6 adds one optional, source-owned Claude checkpoint record. Authorized write-open migrates old stores without inventing recovery state; read-only exact-current-schema commands reject schema 5 without writes until a separately authorized scan/open migration. Public StoredSource and catalogue shapes remain unchanged.
- Existing source replacement methods clear any old checkpoint atomically. A new internal checkpoint-aware replacement validates an opaque adapter checkpoint under the live IdentityContext, compares its public snapshot with the validated source snapshot, and binds it to the next committed revision. No arbitrary string is accepted as durable recovery state.
- A namespaced keyed seal binds source/header/version metadata, scanner semantic limits, original whole-file content proof, nextOrdinal, the exact opaque checkpoint digest, and the canonical public-projection digest to that generation. Row presence and offset columns alone never authorize resume. This seal is integrity under the local identity context, not encryption or protection from a holder of that context.
- Stored checkpoint reads preflight SQL type, count and UTF-8 byte bounds before selecting payload. Corruption, invalid authenticated state, wrong source/key/binding or inconsistent generation/projection fail safely with existing database error codes; do not silently repair or overwrite them through replay. Legitimate current-version/limit incompatibility is a safe full-replay miss under the original CAS.
- Use the existing content-proof framing with the old observedSize to validate every previously observed byte, including a prior unfinished tail. This is deliberately stricter than complete-prefix-only equality: rewriting an unfinished tail produces a replay miss; appending to that unchanged tail can resume. Size, mtime or final boundary alone never authorize resume.
- The reader checks the saved completedOffset is a real LF boundary and checks its existing keyed 4096-byte boundary proof. Resume suffix decoding starts exactly there, with nextOrdinal equal to the previous count of successfully decoded complete records. Total old-plus-new records obey the unchanged limit; suffix count alone never bypasses it. Source-file and max-line ceilings stay unchanged.
- File consistency, raw prefix verification and suffix parsing use one owned regular-file descriptor. Existing symlink/FIFO guards, before/open/final stat checks, bounded byte buffers and close-before-commit semantics remain. Observed in-flight changes, access/read/close failure and cancellation reject rather than disguising themselves as stable misses.
- Re-parse fallback uses a fresh adapter and starts at zero with the originally observed expectedRevision. A changed generation between candidate read, file work and write is stale with no automatic retry. A matching checkpoint does not allow refreshing the CAS expectation.
- New whole-file proof describes the exact bytes supplied to the prefix validator and suffix decoder. No new source proof is minted from an unrelated later read. A stable replay fallback observes its own full parsing read.

### 1. Internal API and unchanged public projections

Keep `createSourceStore(database, keyId)`, `replaceSource`, `replaceSourceSnapshot`, `readSource`, catalogue and existing return/result shapes backward-compatible. Do not add a checkpoint property to StoredSource. Add these internal methods (names are the frozen intended API once approved):

- `readSourceForIngestion(sourceId, context)`: one fresh owned read transaction returning `{source, checkpoint, predecessor}`. `source` is the existing validated StoredSource or null; checkpoint is null or a validated bounded generation record. Reject a pre-existing caller-owned transaction to avoid an obsolete snapshot. Validate the context keyId equals this store keyId. A checkpoint row without an available Claude full snapshot, cache proof or understood relationship capture is corruption. Public readonly consumers continue using `readSource` and never receive checkpoint material.
- `replaceSourceSnapshotWithCheckpoint(input, capture, context, expectedRevision, predecessor?, signal?)`: uses the existing snapshot encoder; capture is null or exactly `{checkpoint, nextOrdinal, maxFileBytes, maxRecords, maxLineBytes}`. Validate current ordinary Claude token and exact projection equality before beginning SQL. A null capture is legitimate optional unavailability, not a partial checkpoint. Under existing BEGIN IMMEDIATE and original CAS, commit validated full snapshot plus optional sealed checkpoint. When predecessor is supplied, synchronously revalidate the previous checkpoint/source inside this write transaction and require exact original optional presence/seal plus the bounded header/public-projection digest before replacing. predecessor is a frozen internal token from the initial read, with exact fields checkpointSeal (string or null) and generationDigest (64 lowercase SHA256 hex or null for absent source). generationDigest covers the fixed public header/lifecycle/cache metadata plus the incrementally computed projection digest, using a versioned fixed-order tuple. It is a concurrency fingerprint, not a new authenticity claim. Every scan candidate-derived write MUST supply it, including compatible resume, stable proof mismatch fallback, version/limit incompatibility and initially absent checkpoint. Undefined is reserved only for the legacy explicit full-replay API without an initial candidate read. Changed revision returns stale, no retry; same-revision changed/corrupt predecessor raises the existing safe database error. Do not refresh expectedRevision.
- `confirmUnchangedSourceWithCheckpoint(token, predecessor, context, signal?)`: same successful result as existing confirmation. It validates source and optional checkpoint together in its fresh owned read transaction, requiring the original optional checkpoint presence/seal and bounded generation digest as well as the existing source/cache/relationship token. The old confirmation API remains unchanged for old callers.

`ingestSourceFile` retains its existing input and result shape and captures a checkpoint for accepted ordinary Claude full replay. A distinct internal `ingestSourceFileFromCheckpoint(store, context, input, candidate)` receives the complete validated `{source, checkpoint, predecessor}` candidate from the new store read, retaining the original expectedRevision and predecessor on every path, including no checkpoint. It validates argument/source binding and rechecks current parser version/options before choosing suffix continuation; incompatible candidates return to a guarded full-replay helper which preserves predecessor, never the unguarded legacy helper or a newly refreshed CAS. Scan uses the new read/confirmation path only for Claude; Codex source flow remains unchanged. No new CLI option or resumed counter is added. Actual prefix-skipping is proven through synthetic ingest/descriptor spies, not public performance assertions.

### 2. Durable row and bounded generation seal

Schema6 table `source_parser_checkpoints` has exactly: source_id (primary key, FK to source_event_headers), contract_version (=1), next_ordinal, max_file_bytes, max_records, max_line_bytes, checkpoint_bytes, checkpoint_json, adapter_limits_fingerprint, generation_seal. Strict SQL constraints establish integer bounds and checkpoint text bytes at most4,194,304, but JavaScript revalidates everything. No raw file identity, stat tuple or source bytes persist. Only ordinary Claude tokens are accepted by the new writer; Codex cannot acquire a row.

Before selecting checkpoint_json, query at most two metadata rows with CASE/typeof/length(CAST AS BLOB) sentinels. Reject duplicate/orphan/missing-table, BLOB/nontext, recorded-versus-actual byte mismatch, oversized or invalid scalars. Only after this bounded preflight may at most one <=4MiB string cross into JavaScript. Reject noncanonical integer -0 in API data. nextOrdinal is the count of complete decoded records from zero and cannot exceed stored maxRecords32768. Scanner limits use existing ceilings and must be positive safe integers; chunkBytes is deliberately not semantic or sealed. adapter_limits_fingerprint is exactly64 lowercase hex: SHA256 of UTF8(JSON.stringify(["agentprof.claude-limits/v1", fixed ordered [name,value] pairs for every actual DEFAULT_CLAUDE_LIMITS entry])). Read actual defaults rather than duplicate values. A valid sealed mismatch is legitimate incompatibility, even when parserVersion is unchanged. This metadata is not a new provider limit.

Use Node's standard SHA-256 for bounded content digests, and ONLY the existing local IdentityContext.fingerprint for authentication:

`fingerprint("source", ["agentprof.claude-source-generation/v1", SHA256(UTF8(JSON.stringify(fixedTuple))).hex])`

fixedTuple is exactly `[1, sourceId, "claude", parserVersion, normalizationVersion, keyVersion, keyId, revision, completedOffset, observedSize, boundaryFingerprint, cacheEvidence.contractVersion, cacheEvidence.contentFingerprint, nextOrdinal, maxFileBytes, maxRecords, maxLineBytes, checkpointUtf8Bytes, checkpointSha256, adapterLimitsFingerprint, projectionSha256]`. Fixed ordering and exact JSON scalar types are part of v1. The tuple is bounded metadata, never the4MiB token itself. Validate keyed-domain shape and compare fixed-length bytes with timingSafeEqual. No new key, credential, prompt or persistent access setup is introduced.

projectionSha256 incrementally hashes the existing encoded/public stored rows using a versioned prefix and each `JSON.stringify([kind, ordinalOrId, rowIdOrNull, rowJson]) + "\n"` frame. Order is events by event_id; then metric rows by kind and ordinal; then relationship status/header frame and relationship rows by kind and ordinal. The relationship header frame explicitly distinguishes null, captured empty and current-policy budget-unavailable. Existing event16MiB + metric16MiB + relationship4MiB preflights bound input to36MiB before hashing; process one already bounded64KiB row at a time, not a concatenated generation JSON string. Exact stored canonical row strings are hashed on read; write hashes the exact strings it inserts. Counts/bytes and every row remain subject to existing validators. Token hash is computed only after its own4MiB preflight.

At initial capture and compatible restore, call the existing strict decoder with current defaults and actual parserVersion and require its private position.recordCount==nextOrdinal, firstOrdinal==0 when nonempty, lastOrdinal==nextOrdinal-1, or all-null positions/count0 when empty. The adapter-only API legitimately permits other initial ordinal bases; production scanner checkpoints do not. Then the restored adapter snapshot is re-encoded with existing validators and must match the persisted public projection. This check catches an incorrectly attached token even before suffix parsing. Projection equality uses the same event ordering and relationship budget policy as storage; it does not require insertion order where existing event readback sorts by ID. All metric/diagnostic/relationship order that is observable today is retained.

Threat model: detects accidental edits, truncation, invalid metadata and unauthenticated checkpoint/generation substitution relative to the local identity key. Existing file proof ties all previously observed bytes to provider/source/parser/options, and the generation seal ties that proof and checkpoint to one committed contribution set. This does not encrypt data, prevent denial of service, authenticate a raw provider's truth, defeat a holder of the local key, or detect rollback of the entire DB together with an old valid signed generation. No independent monotonic root is added. Filesystem stat checks remain bounded observations, not a hostile-kernel or perpetual-snapshot guarantee.

### 3. Deterministic corruption and incompatibility order

Always validate bounded row metadata, current stored source contributions, exact generation seal and recorded bindings first, even when current parserVersion/options differ. A bad seal or structurally corrupt stored source is a hard failure preserving the DB; never classify it as an ordinary miss. A missing checkpoint is an allowed historical/noncheckpointable state and retains ordinary cache/full-replay behavior.

After seal validation, compare recorded parserVersion, adapter_limits_fingerprint and scanner semantic options with the actual current adapter version, DEFAULT_CLAUDE_LIMITS and selected options. A valid sealed mismatch is incompatible: full replay under original CAS, without attempting to coerce or restore old state. This permits the independently planned Claude parserVersion2 search slice. An old token is not decoded under a new semantic codec merely to discover incompatibility. Its original writer validated the ordinary token before sealing it; that is the extent of the authenticated historical claim. Fixed generation contract version other than1 is rejected safely, not silently discarded. Current-compatible state must restore successfully through the existing Claude API with current defaults; any failure or projection disagreement is hard corruption.

Current public reader/stats shapes need no new data. They may continue reading validated public rows without materializing the unused checkpoint. The scanner's new Claude path performs the strict checkpoint validation; this optimization cannot make raw token data appear in reports or errors.

### 4. Same-descriptor reader sequencing and fallback

Add `readSourceSuffixWithProof` in source-prefix.ts, not a new generalized reader framework. It receives the validated prior header/proof/options/boundary and ordinal count. Reuse existing startOffset support in jsonl.ts without modifying that file.

1. Validate path/options and current size bounds, then use existing no-symlink/regular/O_NOFOLLOW/O_NONBLOCK open and before/open identity checks. Current size smaller than old observedSize is a potential stable mismatch, not yet success. Check final path/handle state and close before returning a stable mismatch. In-flight changes/access/close failures reject.
2. If current size is large enough, stream exactly old observedSize bytes using a bounded buffer into an old-proof writer with recorded old options/size. Simultaneously feed only bytes before saved completedOffset into a new-proof writer framed for the current observedSize/current options. Retain at most the final4096 bytes of that completed prefix. Validate exact old whole-file proof, actual LF at completedOffset and existing boundary fingerprint. At offset0 boundary must be null. A token never proves these bytes by itself.
3. If the old whole-file byte proof is a stable mismatch, discard both writers, perform final path/handle checks, close and return mismatch; ingest then opens the file through a guarded byte-zero helper with a fresh adapter and the original CAS plus predecessor token. If the whole-file byte proof MATCHES but the saved completedOffset is not a physical LF or the boundary fingerprint disagrees with those exact bytes, return a distinct internal corrupt_checkpoint result and raise the existing safe DATABASE_ACCESS_FAILED after cleanup, preserving all rows. This is contradictory authenticated metadata, not a changed-source miss. Do not hide it by replay. The fallback's own parsing read generates its own proof. An observed failure is not downgraded to mismatch.
4. If matched, parse from completedOffset on the SAME descriptor using readJsonLinesFromFile. Its raw callback feeds the new-proof writer for every suffix byte. The previous pending tail is deliberately re-read by the decoder, so new proof uses exactly decoder-consumed suffix bytes; the raw probe never pre-feeds those pending bytes into the new proof. No pending-tail bytes are buffered as parser state.
5. Begin descriptors at saved nextOrdinal; total records = saved count + suffix records and must not exceed maxRecords. Current file, line, adapter and store limits are unchanged. Require final checkpoint.bytesRead==currentSize-completedOffset and final nextOffset+pendingBytes==currentSize. Compute new boundary from the exact bytes already observed by prefix validation and suffix decoding, never a later disk reread, then run existing final named/handle stat checks. Use a bounded rolling view of at most4096 previous bytes plus the current reader chunk (at most64KiB), and snapshot the last4096 bytes ending at each accepted complete LF. Preserve that completed-boundary snapshot while arbitrarily long bounded unfinished tail chunks arrive; never let pending-tail bytes evict the saved completed boundary. The same-read rule also applies to new full-replay checkpoint captures through readSourcePrefixWithProof, without changing jsonl.ts or permitting whole-file buffering. Close before exposing a successful proof or touching SQLite. Cancellation or close failure discards the candidate generation.
6. Export the final adapter checkpoint with final completedOffset and total nextOrdinal. If export is unavailable (including4MiB budget), still commit accepted public evidence with no checkpoint. Commit through the new method and original predecessor token/revision. The old rows/checkpoint are replaced together; no checkpoint-only update is allowed.

This reads previous bytes and may re-read a small unfinished tail; it skips adapter ingestion of the verified complete prefix. It is not an I/O-free cache and establishes no speedup or memory savings. A very long bounded pending tail may be re-read up to the existing file limit; no additional tail allowance or giant buffer is added.
