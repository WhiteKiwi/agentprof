## Goal and review findings

Observe failed-attempt contribution in admitted same-session/turn/operation Recovery chains. Preserve resolved/unresolved distinction and the original failure/success references. This subset does not require equal error fingerprints and is not the separate Retry Loop diagnostic. Necessary retries can be included. No avoidability, root-cause, waste, effect or savings inference follows.

At original head `a4fa404fa4a9ff8eb8299d05ae02d14d8b2c5cd6`, `failedAttemptDurationSumMs` sums endpoint differences instead of stored durations, so a source-reported 20 ms process with a 1000 ms lifecycle incorrectly yields 1000 ms. The source summary adds chain unions, so two independently valid overlapping operations can be counted twice. It also pools distinct sessions and interval evidence. These are review findings; executable reproduction and the exact correction plan remain pending separate research.

## Contract

- Reuse one unchanged Recovery analysis for chain admission, identity, chronology and source/provenance suppression. Unknown/unavailable chains do not become zero. Unresolved chains retain their observed failure contribution.
- A failed duration uses its stored finite nonnegative `durationMs` at most `Number.MAX_SAFE_INTEGER`, including fractional milliseconds, and supported native representation with explicit `durationScope` and `timingEvidence`. Match the existing native failed-duration contract: structured shell source-reported process runtime, structured MCP source-reported invocation latency, or exactly consistent paired invocation duration. Never replace it with interval length. Missing/estimated/invalid timing remains unavailable; separate incompatible duration contracts. Expose measured/eligible counts and reason instead of silently summing a convenient subset.
- A chain's overhead is the union of its positioned failed intervals. Source-level union spans all chain failures only within a compatible `(sessionId, intervalScope, intervalTimingEvidence)` partition. Show each partition separately. A scalar elapsed total is unavailable when more than one compatible partition exists. Empty evaluated input may retain zero; suppressed/unavailable input remains null.
- Use checked safe arithmetic for every duration and interval total. Preserve valid zero intervals/durations. Success duration and waiting/edit gaps are excluded.
- Preserve one pinned source generation, privacy, input immutability, deterministic ordering, bounded complete JSON and bounded human detail with exact omissions. Include Recovery partial/unavailable counts/reasons and generation/readiness context so partial data cannot appear complete.
- Only this metric's production files, stats CLI hunks, its new tests and additive docs are in scope. Existing parsers, database, Recovery, dependency/lock, workflows, insights/report/open and historical tests are unchanged. Default/false behavior and all existing stats selections remain compatible.

Separate ordinary-evidence research follows this draft. The implementation plan and owning issue's concrete Verify/claim precede a separate developer's changes.
