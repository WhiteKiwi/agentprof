## Product behavior

`agentprof report --source FULL_ID --output NEW_HTML` writes one offline, static, measured HTML file from one existing source prefix. Both flags are mandatory and nonrepeatable. Global `--json` and `--data-dir` are allowed before or after the command. Reject all roots, `--last`, `--open`, unknown options and extra arguments before store/output I/O. Reject empty/whitespace-only paths and every Unicode C0/C1 control (U+0000–001F, U+007F–009F) in report data/output paths, including ESC and TAB; do not change other commands' path validation. Output paths have a 4096 UTF-8-byte limit; retain legal spaces and Unicode. Missing either mandatory flag returns `REPORT_SELECTION_REQUIRED`; present but invalid values/duplicates/conflicts return `INVALID_ARGUMENT`. Validate invalid/conflicting values first when both conditions occur.

No scan, source listing, opener, global totals, network, server, JS, synthetic substitution, raw log copying or source freshness check. `open` stays NOT_IMPLEMENTED. Existing stats/insights semantics and all non-report stdout/stderr/status remain byte-equivalent except explicitly changed top-level help description/report summary and report help. Report errors and top-level description intentionally supersede the old report placeholder.

Store selection uses installed key binding and existing read-only-store validation. Exactly one `readSource` and exactly one unchanged `summarizeSource` plus `analyzeSourceSlowTool` call consume the same validated source object inside one pinned transaction. Build a new allowlisted owned model there, close the store, then render and publish. No calls to `runStats`/`runInsights`, reopening, analyzer changes or independent query generations.

The report identifies source/provider/revision, byte prefix, observed size, availability, persisted scope, parser versions, support and coverage. The byte interval is not a calendar interval; queryPeriod remains null and sourceFreshnessChecked false. Inventory, observation, event and response counts retain their units. Show summary suppression and SlowTool suppression/assessment/candidateAssessmentReason separately. Show SlowTool partition status separately from candidate results. Do not promote null to zero or missing coverage to healthy empty.

Duration summary copies original n/sum/mean/max/p50/p95/lowSampleP95/overflow flags; accepts finite nonnegative fractional milliseconds through MAX_SAFE_INTEGER. Counts remain safe integers. Summary cohorts and native-call SlowTool eligibility have distinct headings and denominators. No cross-partition sum/ranking. Usage copies existing response cohort count components, mapping/finality, overflow and limitations; cache/reasoning are labeled components/subsets, never added again to input/output/total. No usage population denominator is invented.

SlowTool cards copy rule/version/thresholds, grouping, exact statistics, denominatorN/denominatorSumMs and unrounded admitted-duration fraction, evidence counts, confidence and complete unchanged safeguard prose. `candidates=null` means unavailable, with its reason; `[]` means no candidate met thresholds in evaluated observations, subject to zero-denominator/partial/unevaluated status. Never claim waste, savings, full session/history, backend/network latency or proven root cause.

## Selection, bounds and links

The model contains at most six session panels. The session universe is the deduplicated union of sessionId values in summary durations, summary usage and SlowTool partitions (candidates must reference a known partition). Sort by UTF-16 lexical comparison, not locale, and select the first six. Empty/suppressed data can produce zero sessions; source-level state remains visible. This is stable selection, not importance ranking.

Within each selected session form a union of `(durationScope,timingEvidence)` keys from summary duration cohorts and SlowTool partitions; sort by tuple lexical comparison and show the first four. Summary-only and SlowTool-only partitions retain explicit empty/unavailable context for the other dimension. Never combine partition denominators. Select known-sum rows first by sumMs descending, then category, toolName (null sorts first), commandPattern (null first); show ten. Select unknown-sum rows separately using the same lexical tie-break; show ten. Unknown rows correspond to actual analyzer null sums such as overflow, not fabricated excluded-event cohorts. Show exclusions separately. Ties do not depend on original array order.

For each selected session sort usage cohorts by `(provider,mapping,finality)` and show four. Show at most ten cards overall, selected by displayed-session order, displayed-partition order, then original analyzer candidate order within that partition. Only cards whose session and partition context are displayed are eligible. No cross-partition magnitude ranking. Each card links to its generated session and partition anchors; source/coverage context links resolve. Generated monotonically numbered IDs only; no source strings become anchor IDs. No external links.

At source level report exact total/shown/omitted sessions, duration partitions, duration cohorts, usage cohorts and candidates (unknown candidate total stays null). At each shown session report partition and usage totals/shown/omitted; at each shown partition report known/unknown row and candidate totals/shown/omitted. Counts omitted because of a parent bound are included in source totals. No omission changes original analyzer denominators or eligibility counts. Evidence ID arrays are converted to counts, never copied. Complete evidence remains accessible through existing stats/insights JSON commands.

Bound allowlisted text by UTF-8 bytes: opaque source/session IDs 160; closed enum/code/tool fields 96; safe command pattern 512; each fixed rule safeguard paragraph 2048; each fixed limitation 128; arrays of limitations/observed-shape strings 64 entries, 128 bytes each. For a valid stored safe command pattern exceeding 512 bytes render the fixed label `safe pattern omitted (display limit)` and preserve group identity/order using the original bounded analyzer key internally. Never truncate safeguard prose; overflow rejects with REPORT_LIMIT before file creation. No raw field is silently substituted into text. Final HTML <=1,048,576 UTF-8 bytes, measured before temporary output creation. Intermediate model collections obey these caps before rendering. Analyzer input already respects persisted source ceilings; no arbitrary-size public object API.

Builder and renderer are internal functions consuming validated store/analyzer results and newly allocated model objects. Descriptor checks reject unexpected keys/accessors on ordinary owned-model objects; do not advertise safe inspection of arbitrary Proxy objects. No raw StoredSource, sourceRef, metadata, file paths, command input, prompts, outputs, key IDs/keys or hidden JSON are serialized.

## Publication and receipt

Only Linux/macOS and same-directory no-replace hard-link publication are supported. Require existing, stable, trusted parent directories. Before creation inspect parent components with lstat/realpath and reject symlinks or a destination inside the canonical private data directory (including the directory itself); reject existing target of every kind. Fully render first. Create unpredictable same-parent temporary regular file using exclusive open plus O_NOFOLLOW when available, mode 0600; verify handle/temporary-path device+inode identity, regular file and 0600, perform a complete write loop, sync file, close, recheck temp identity and canonical parent identity, then hard link temp to absent target. Verify target device/inode/mode matches owned temp. No overwrite rename fallback. Unsupported link/filesystem semantics fail before publication. Concurrent target creation fails without overwriting it. Never unlink the target.

This does not claim safety against a hostile ancestor renamed between pathname operations; trusted stable ancestor ownership is a precondition. Failure before link is not published; cleanup removes only the owned temp after identity check. After successful link, every failure is a published outcome, including target verification, temporary unlink, directory open/sync/close failures. Always retain published=true in that path; do not emit a misleading retryable unpublished error. Never automatically retry. Report durability as `synced`, `unsupported`, or `unconfirmed`; cleanup as `removed` or `retained`; targetVerification as `verified` or `unconfirmed`. Unsupported directory sync is explicitly labeled, never silently called durable.

Successful publication emits exactly one stdout receipt, human or `{schema:'agentprof.cli/v1',ok:true,command:'report',result:{mode:'selected_source',sourceId,revision,output,published:true,bytes,durability,cleanup,targetVerification}}`. Output is canonical requested target path, locally disclosed only in receipt; HTML contains no path. Clean verified publication exits 0. Any postlink issue emits the same truthful published result with ok=false, status `published_with_warning`, fixed warning code(s), and exits 1; no misleading stderr-only failure. A prelink failure uses existing safe stderr envelope and exit 2. No arbitrary exception text or temporary path is disclosed. Prelink cleanup failure uses a fixed report error code; no assertion that cleanup succeeded.

Frozen new codes: REPORT_SELECTION_REQUIRED (Select --source <full-source-id> and --output <new-html-file>. Run agentprof report --help.); REPORT_LIMIT (The report exceeds the supported display limits.); REPORT_OUTPUT_UNSAFE (The report output path is unsafe or already exists.); REPORT_OUTPUT_FAILED (The report file could not be published.); REPORT_OUTPUT_CLEANUP_FAILED (The report was not published and its temporary file could not be removed.). Postlink receipt warnings use closed literals `target_verification_failed`, `temporary_cleanup_failed`, `directory_sync_unsupported`, `directory_sync_failed`, `directory_close_failed`. No diagnostics for raw filesystem errno strings.
