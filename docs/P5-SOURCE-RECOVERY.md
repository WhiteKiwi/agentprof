# Selected-source observed recovery time

Implementation scope: [issue #54](https://github.com/WhiteKiwi/agentprof/issues/54), a narrow child of [P5 #6](https://github.com/WhiteKiwi/agentprof/issues/6).

## Goal and boundary

Add the Recovery Time metric from [METRICS §7](METRICS.md#7-recovery-time) to `stats --source FULL_ID --recovery`. The view measures the interval between a confirmed failed result and a later confirmed successful result for the same operation in the same explicit Codex turn. It does not diagnose Retry Loop: ordinary error fingerprints are not sufficiently established for the same-error rule. Recovery can include other work or waiting; it is not process runtime, causation, waste or avoidable time.

The input is one validated `readSource` generation. Existing source freshness, cross-source reconciliation and readiness limits remain explicit. No raw input is reopened, no scan runs, and the store/key/modes/sidecars remain unchanged. No parser, normalization, schema, report, dependency or package behavior changes. Claude remains unsupported here because ordinary Claude events deliberately have null turn identity. Source-local does not mean complete session or complete history.

## Evidence admission

1. Reuse `analyzeSourceFailures` without changing it for native terminal/provenance admission, unavailable/absent/limited/ambiguous/unsupported source gates and unresolved session provenance. Support only the current matching Codex parser/capability version. Keep inherited partial-shape coverage explicit.
2. Candidate operations are native Codex `exec_command` shell and `mcp` events. Model/other call classes remain counted exclusions. A candidate lacking `turnId` or `operationKey` creates a session-level identity gap: it cannot safely be assigned to an unaffected operation. Do not decode, emit or use display patterns in place of private operation identities.
3. Group by exact source-local session, non-null turn and operation key. Contradictory operation class/tool/category tuples make the group unavailable. Pending/cancelled/unknown outcomes, completed no-match/change-detected/unknown outcomes, or a candidate not admitted by the inherited terminal proof make the affected group unavailable. Do not silently remove ambiguous attempts and connect the surviving subset.
4. A failed attempt must be `failed/error`; a resolving attempt must be `completed/success`. Require explicit valid start/end boundaries with nonnegative safe differences. Supported timing representations are Codex structured `source_reported/item_lifecycle` and ordinary call/result or poll `paired_timestamps/invocation_latency`. The group may not mix these representations. Never back-calculate a boundary from duration.
5. Reuse terminal proof admission, then require the native call or structured observation to agree with the event's explicit turn. Ordinary Codex result/poll observations may have null turn IDs. Supporting references contain the ordinary call plus the decisive result/poll at the event's source position, or its decisive structured observation. A paired call must precede its result in the same source file. Omit orphan, wrapper, foreign, unrelated and superseded observations.
6. Require agreement between source-result order and explicit boundaries. In ascending decisive source offset order, completion times must strictly increase and each next start must be at or after the previous end. Equal start/start or end/end timestamps, source/time-order contradictions or overlapping same-operation attempts are ambiguous; do not break chronology ties with event IDs. Adjacent non-overlapping intervals are allowed when the previous end equals the next start and their start/start and end/end values are distinct. Preserve deterministic aliases/order without interpreting lexical IDs as time. Event-array and observation-array permutations must preserve the result.

Conservative group/session suppression favors an honest unavailable result over a falsely recovered chain. The view reports why it cannot decide. Missing identity in another session must not suppress a fully evidenced session. Unrelated operations with complete identities cannot resolve one another.

## Chains and statistics

A failed result opens a chain. Further failed attempts for that same operation and turn join it. The next eligible success resolves it. Successes before any failure are inventory only. A subsequent failure after a resolved chain starts a new chain. At the stored observation boundary a failure chain without a success is `unresolved`: its terminal success and recovery elapsed value are null, not zero or the last source timestamp.

Each chain exposes source-local aliases, session/turn identity, failed and successful event references, the first failed result time, the successful result time when resolved, `failedAttemptCount`, `attemptCount`, `resolved` and `recoveryElapsedMs`. The recovery value is successful-result time minus first-failed-result time, not first-call time or failed-duration sum. Known failures that are blocked by a group/session gate are separately visible; they do not become resolved/unresolved chains with invented timing.

Use schema `agentprof.source-recovery/v1`, metric `recovery_elapsed_time`, and version `codex-same-turn-operation-v1`. JSON retains all bounded evidence. Report exact resolved/unresolved/unavailable counts and group/session reasons. Resolved-only distributions use nearest-rank p50/p95, include sample counts and the existing `n < 20` low-sample warning, and remain partitioned by session and interval scope/evidence. There is no cross-session or mixed-timing pooled elapsed total. Empty/no-failure and unavailable results remain distinguishable. Recursive freezing must not alias mutable input collections.

The analyzer inherits at most 4096 events and 8192 observations, rejecting over-limit input before analysis. Build observation/session/operation indexes once; sorting is at most `O(n log n)` and scans are linear. Do not rescan all source observations for each attempt/group or create pairwise attempt products. Human output shows at most six sessions, six groups, six chains and six resolved-only distributions, with exact shown/omitted counts for each section and one limitations paragraph. The bounded session section preserves missing-identity and inherited provenance reasons even when a session has no assignable operation group. Keep the complete human output below 160 lines/32 KiB and complete JSON below 8 MiB for maximum admitted input without clipping evidence. Unavailable counts refer to groups and known failed candidate attempts; inherited all-class failure inventory remains separately named. Do not invent an unavailable-chain count when chronology is not known.

## Implemented interface and focused qualification — 2026-10-03

After the registered #54 claim and parent GO, the separate development contributor implemented the four reserved production paths. `partitions` retain session gates and unassigned identities; `groups` expose snapshot-local operation aliases, source event IDs and complete group-gate reasons. `chains` and `distributions` are null when no candidate group can be evaluated, while evaluated empty/no-failure results use empty arrays and zero chain counts. The summary's known-failure counts cover Recovery candidates only; the separately named inherited inventory/provenance covers the broader native failure admission. A blocked group is not assigned an invented chain count. Each chain keeps its failed/successful event IDs and exact supporting observation IDs; group proof arrays retain unavailable-group and outside-success evidence without duplicating chain proofs. No private operation key or source reference is emitted.

Native terminal admission is reused once. An event/observation index and session/operation buckets bound repeated access; chronology is determined by decisive source positions together with explicit endpoints. The implementation rejects whole groups before publishing any chain, including uncertainty after an apparent resolution and unsafe endpoint subtraction across otherwise valid intervals. The formatter separately caps sessions, groups, chains and distributions at six and reports each exact omission count. Missing-identity-only sessions remain explainable even when they have zero groups.

Focused verification ran on Linux x64, Node **24.19.0**, pnpm **10.34.6**, one Vitest worker and a **512 MiB** heap. Typecheck and build passed. Final result: **122 passed, 0 failed, 1 skipped across three new test files** (62 analyzer, 38 integration, 22 executed CLI cases); the skipped case requires an actual installed artifact and remains a parent gate. The ordinary paired, structured, poll and MCP scan/store/reopen fixtures produce the independently specified 5,000 ms result after raw deletion. Actual ordinary Claude keeps null turns and reports the unsupported contract. Default/false stats modes, predecessor human/JSON outputs, exact help except the two added stats rows, unchanged stored report HTML and opener validation passed. The complete test set preserves source/key file names, bytes and modes and verifies one pinned read, one selected Recovery call and one reused native admission call.
