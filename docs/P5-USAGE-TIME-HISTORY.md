# Versioned usage timestamps and daily token evidence

## Specification — 2026-10-03

Continue the owner's remaining-development request with actual usage timestamp capture and daily token evidence, not another presentation-only view. Base is PR137 `cce10ca739c6c2954dc661d6149dcbd587077720`; PR139's unified layout is independent and must not be duplicated. Existing default parser and scan output contracts remain unchanged.

`scan --usage-timing` opts into Codex parser2 / Claude parser3. These versions add a nullable `usageObservedAt` field to source observations: a canonical timestamp from that record for usage observations, null otherwise. Never use file timestamps, scan time, response IDs, neighboring calls or turn dates as fabricated usage dates. Default Codex1 / Claude2 adapters retain their exact old fields. Both codecs authenticate the selected parser version; storage accepts only that version's exact observation shape. Same-mode resume/unchanged checks retain timestamps; mode changes fully reparse under the existing original-revision CAS rather than restoring an incompatible checkpoint. A later scan without the opt-in deliberately uses the legacy contract, not an undocumented sticky mode. No schema migration is needed because versioned observation JSON already belongs to the atomic metric rows and sealed source generation.

`history --tokens --source ID --from UTC --to UTC [--offset +09:00] [--json] [--output new.html]` shows selected-source token evidence on the existing half-open/fixed-offset calendar contract. It is opt-in and must not alter native-call history. Do not combine this initial stored-token query with --provider/--input; collection is explicit via scan --usage-timing. The query must validate before private I/O, read each selected source once inside one read-only transaction, preserve source/provider/version/revision/availability and use bounded source/copy/observation/JSON/HTML budgets.

Group response identities across explicitly selected sources by provider/session/response, not file path or recency. Equal copies count once. Conflicting counts, scope, mapping, selection or finality withhold the group, with exact reasons. Cumulative/unverified snapshots are inventory, never summed as increments. Missing response IDs, ambiguous provenance, missing evidence and unavailable/state-limited sources are excluded with truthful coverage. An unavailable historical copy does not invalidate an independently admitted available copy but stays in the source inventory; no complete-account-history or freshness claim.

For admitted response evidence, distinguish eligible-final and provisional-response partitions; never add these populations into a final token total. Ordinary Claude message stop_reason does not establish finality. Provisional counts are explicitly unverified response observations, not billing/final-use claims. Choose the earliest known timestamp among ordinary observations that match the selected response counts/mapping/finality, preserving missing-timestamp observation counts. This is a recorded-observation day, not a billing day, response completion time or tool/phase allocation. Missing time has no invented day. Keep out-of-window, undated, conflicted and nonresponse inventories separate. Do not zero-fill unobserved days. Cached/reasoning fields are components of the existing provider mappings, not additions to total. Null components stay null; safe-integer overflow yields null plus explicit overflow reason.

Existing other analyzers may admit the new timestamp-only versions only where they already accept the corresponding legacy semantics; add narrowly tested version aliases without changing formulas, thresholds or finality. Exploration remains #50's responsibility. Release/default-mode promotion is not part of this change.

## Findings and rationale

The existing adapters already parse a safe record timestamp internally, but usage observations do not retain it. Usage rows and observation rows, relationships, file proofs and parser checkpoints are already committed and authenticated in one source generation. The existing snapshot/readback projection compares canonical observation JSON, so timestamp capture must participate in both adapter checkpoint codecs rather than be attached after parsing. File proofs bind parserVersion; using distinct versions prevents old unchanged results and checkpoints from masquerading as captured timestamps. Existing summary eligibility, source-history calendar parsing and no-overwrite static report primitives supply the established contracts.

Claude's documented input accounting separates uncached input, cache-read and cache-write components (https://platform.claude.com/docs/ko/build-with-claude/prompt-caching). The repository's CLAUDE-PARSER/CODEX-PARSER and usage validators remain authoritative for log finality; API semantics alone are not proof that an arbitrary log snapshot is final. This feature does not introduce new empirical provider support or fabricate missing observations.
