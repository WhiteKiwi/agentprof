## Admission, identity and denominator

The input is one validated `StoredSource`, not arbitrary JSON. Reuse unchanged `analyzeSourceFailures(source)` once as the conservative ordinary terminal-provenance gate. For each evaluated session, use its `completedEventIds` membership; never rederive completion from timing, exit codes or transport status. Keep this conservative inherited reason visible rather than silently narrowing the denominator.

Only Claude rows with exact `(kind, category, toolName) = (file_read, read, Read)` and admitted completed status qualify. Failed Read, pending, cancelled, unknown, non-Read and inconsistent-class rows are excluded with separate counts. An untimed completed Read is eligible; time is not a gate. Ordinary call + decisive result/source-position matching is supplied by the unchanged provenance analyzer. The count unit is one unique normalized **event ID** representing an admitted invocation in this stored generation. Do not count observations, message UUIDs, result updates, source lines or usage rows. Do not deduplicate different event IDs merely because `operationKey` is equal: repeated identical reads are distinct calls. Existing adapter/store identity collapses repeated representations of the same invocation. No cross-source or physical-execution uniqueness claim is made.

Partition by source/provider/revision/session. Group file cohorts within each session by the existing `fileFingerprint`, which includes provider, observed project context and the exact path representation. Different read ranges/options do not split the basic file cohort. Different project contexts produce distinct fingerprints even for the same textual path. No project identifier is recoverable from the hash; do not emit project partitions or project totals, or claim the session belongs to one project. Relative/absolute spelling, aliases and symlinks are not reconciled. No cohort or ratio merges different sessions or sources.

For an evaluated session, let C be all provenance-admitted completed Read event IDs, N = |C|. If N=0, counts/ratio assessment are unavailable (`no_eligible_reads`), not 0%. If any member of C has null fileFingerprint, retain candidate and missing-identity counts/IDs but set validReadN, uniqueFileN, revisitN, revisitRatio and cohorts to null (`identity_unresolved`). Do not compute a ratio from just the known-identity subset. Otherwise U is the number of distinct keyed file identities, validReadN=N, uniqueFileN=U, revisitN=N-U and revisitRatio=(N-U)/N using ordinary division without rounded decision logic. N=1 or U=N yields observed 0. There are no diagnostic thresholds or severity.

Source relationships being absent, captured-empty or budget-unavailable do not by themselves prove either completeness or invalidity of this narrow metric. Do not promote support from a captured graph. Existing positive ordinary metric observations and the inherited execution-relation suppression are the only provenance admission here; relationship storage is not a graph resolver.
