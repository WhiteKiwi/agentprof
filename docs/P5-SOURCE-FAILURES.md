## Frozen status/provenance contract

Status admission is independent from timing. Use only native classes: Codex shell/exec_command, mcp/mcp, file_edit/apply_patch; Claude shell/Bash, file_read/Read, file_write/Write, file_edit/Edit, search/Grep or Glob, mcp/mcp, browser/browser. Match category exactly (shell admits test/build/search/read/other). This closed list does not promise that each adapter can emit a terminal positive for every class. Exclude other classes, cancelled, pending and unknown with disjoint reasons.

Use adapter-produced completed/failed status, never derive it again from exitCode or transportStatus. Each admitted row needs ordinary-origin observations linked by its exact event ID, correct provider shape, and a decisive observation at its normalized sourceRef fileId/byteOffset. Every linked execution observation must have ordinary origin and correct provider shape; Claude sessionId must agree. Mixed/copied/contradictory observations cannot be rescued by a convenient duplicate.

- Codex `event_msg` terminal rows require matching structured observation with a reachable normalized status/outcome/transport tuple: failed/error requires failed transport; completed/no_match or completed/change_detected requires shell class and failed transport; completed/success or completed/unknown requires completed transport. This consistency gate does not re-derive exit semantics. Prefer the structured representation whenever the normalized row's recordType is event_msg, independent of whether timing is present. Nondecisive fallback observations do not override that precedence.
- Codex `response_item` terminal rows require an ordinary call and a matching result or poll observation. Their stored transportStatus remains unknown by adapter design. The normalized terminal status and decisive result source position together are the status contract; do not describe unknown transportStatus as terminal evidence. Pending polls normalize pending and are excluded before admission. Structured/result representation mismatch at the decisive position is contradictory. No independent physical execution claim is made.
- Claude terminal rows require ordinary call plus decisive result whose observedResult has completionKind=invocation_result, unassignedAcknowledgement=false, isError exactly matching failed/completed. Timestamp equality is not a status gate: invalid negative elapsed can clear normalized endAt while preserving confirmed terminal status. Background acknowledgement does not qualify; timing may remain null without removing the failure.

Partition by source/provider/revision/session. All otherwise native completed/failed rows, including untimed, zero and missing identity, are tentative terminal members. If any such row has missing/contradictory provenance, suppress that session's confirmed counts and cohorts rather than shrink the denominator. Expose tentative event IDs, unresolved IDs and exclusions. Resolved sessions expose completed, failed and terminal event IDs/counts. Each session also exposes disjoint status exclusions, including excluded unknown-status counts beside its confirmed denominator; no overall failure rate label is permitted. Sessions with only excluded rows remain visible as no_eligible_events with null confirmed counts. There is no global failure rate. An evaluated nonempty terminal subset may have failed=0; suppressed or no eligible population has null assessment. Other session partitions remain evaluable and are explicitly partial.

Failure cohorts use only `(kind,category,toolName,commandPattern)` as safe display labels, never same operation/error identity. Expose failed event IDs and evidence observation IDs (supporting calls plus decisive results/structured records), plus missing operation/error identity counts; never emit fingerprint values or infer retries, distinct errors, recovery, causes, waste or savings.
