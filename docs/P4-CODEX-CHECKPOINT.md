## Goal and externally observable boundary

An ordinary single-source Codex adapter may export bounded, raw-free state and restore it into a fresh adapter under the same identity context, source, parser contract, semantic limits and caller-supplied position. For eligible state, uninterrupted parsing and export/restore continuation must produce exactly the same final snapshot, safe retained-state inspection, ordered diagnostics and every suffix upsert batch. A second checkpoint cycle must preserve the same invariant.

This is valuable because public snapshots omit result replay digests, pending results, process/poll links, command exit policy, call/structured priority, source ownership/version evidence and cumulative snapshot history. Snapshot reconstruction cannot preserve later pairing, conflict or reset/reorder behavior. The API is a prerequisite for future integration; it does not read files, seek, persist to SQLite, enable scanner resume, alter CLI output or promote either readiness flag.

Ordinary means no reachable `trustedFixtureContext` was provided to any ingest attempt in the adapter lifetime, including an empty context, inherited property or accessor. A synthetic JSONL file used without that context is ordinary inert input. Multiple streams, forks and ambiguous origin inside one physical source remain eligible if the complete retained state fits. Multiple physical sources, nonsequential physical positions, caller conversion hooks or values not losslessly representable in v1 make export unavailable without changing live parsing.

The checkpoint authenticates serialized adapter state under a locally supplied signing context. It does not encrypt it, establish authenticity of provider logs, authenticate the original prefix bytes or defend against a caller possessing that signing context. The caller MUST independently establish exact source-prefix equality, an actual completed LF boundary, matching file generation and atomic relationship with stored contributions before any future seek. Neither mtime/size nor the tag replaces that proof.

## Additive API proposal

- `CodexAdapter.exportCheckpoint(binding, options?)`: frozen `{status:"captured", checkpoint:string}` or `{status:"unavailable", reason:<fixed enum>}`. No partial token. Use the merged Claude API's shape; callers can measure UTF-8 bytes without another result field.
- `CodexAdapter.restoreCheckpoint(context, encoded:unknown, expectedBinding, limits?)`: static factory returning frozen `{status:"restored", adapter:CodexAdapter}` or `{status:"rejected", reason:"invalid_checkpoint"}`. Never mutate an existing instance.
- Binding: exact `sourceId`, `completedOffset`, `nextOrdinal`. Source ID is the existing `fingerprint("source", ["codex", fileIdentity])`; raw file identity is never serialized.
- Export reasons: `unsupported_state`, `unsafe_positions`, `incompatible_binding`, `checkpoint_budget`. Invalid/unrepresentable retained state uses unsupported_state; invalid caller binding/options use incompatible_binding. Restore alone reports invalid_checkpoint.
- Effective semantic limits are the existing nine `CodexLimits` values, unchanged: events, turns, usage, sources, streams, links, observations, metadata, diagnostics. Defaults stay 4096/4096/4096/256/256/1024/8192/8192/8192; existing 1..1,000,000 constructor validation remains. Store the full effective values and require exact restore equality, including otherwise-unused ordinary limits.
- Fixed UTF-8 envelope ceiling 4 MiB, row ceiling 64 KiB, depth 16, total structural-node ceiling 4,194,304. Optional `maxBytes` may only reduce export ceiling, never alter parsing admission or restore policy. No dependency, DB validator import, schema migration or shared parser-type change.
- Put narrow API and private crossing types in new `src/parsers/codex/checkpoint-types.ts`; implement adapter-specific codec in `checkpoint.ts`. Re-export relevant public types/constants through the existing Codex module if needed. Preserve current `snapshot`, `inspectRetainedState`, factory, ingest and capability bytes. Checkpoint schema version is separate from the actual current Codex `parserVersion:1`; use one actual parser-version authority, not a second unrelated literal.

## Position contract

Before existing record-shape early returns, observe the descriptor without invoking getters. Track only keyed source ID, firstOrdinal, lastOrdinal, lastByteOffset and recordCount. First ordinal can be any nonnegative safe integer, including 0 or 1. Later ordinals must be exactly previous+1, and start offsets strictly increase. Track valid descriptors even when the raw record is primitive/null/array or has malformed payload; checkpointing must not silently omit attempted positions.

For a nonempty prefix, `lastOrdinal+1 == nextOrdinal`, `lastByteOffset < completedOffset`, and `recordCount == lastOrdinal-firstOrdinal+1`, with safe arithmetic. Empty state requires `completedOffset=0`, nullable first/last/offset and zero count; caller-selected `nextOrdinal` is authenticated. Blank lines/BOM can precede the first record. This tracker cannot prove no physical lines were skipped.

A nonempty attempted prefix may still have an empty source-state map: primitive/array records are rejected before current source admission. Do not equate attempted descriptor count with recognized-source map size. Re-export immediately after restore, before any new descriptor, must retain EXACT authenticated completedOffset and nextOrdinal rather than silently advance a caller boundary.

After restore, first continuation must use exact source/next ordinal and `byteOffset >= completedOffset`. Subsequent records obey consecutive ordinal/increasing offset. Wrong descriptor/source/position permanently disables further export but preserves existing ingest behavior. Semantic replay at a later physical location is allowed. Invalid descriptors, source changes, trusted context, inherited/accessor alias hazards and negative-zero numbers are never normalized away for the checkpoint. Positive zero remains supported. Bounded prototype/descriptor inspection must reject proxies without invoking traps, using the merged Claude safety approach.

## Envelope and owned-data validation

Outer string has exactly ordered fields `schema`, `payload`, `tag`, where schema is `agentprof.codex-checkpoint/v1`, payload is an opaque JSON string and tag is `fingerprint("source", [schema, sha256(UTF8(payload)).hex])`. Compare validated fixed-length tag bytes with `timingSafeEqual`. Payload has exact fields `schemaVersion`, `provider`, `parserVersion`, `normalizationVersion`, `keyVersion`, `keyId`, `sourceId`, `completedOffset`, `nextOrdinal`, `limits`, `position`, `state`.

Reject nonstrings and over-budget strings before parse; preflight JSON lexical depth including quoted strings/escapes. Outer canonical serialization/order rejects duplicate/extra/reordered fields. Authenticate payload before its bounded parse; inner canonical serialization and exact field schema remain mandatory even with a valid tag. Every object uses exact own-data fields and ordinary/null prototypes; arrays are dense; no getters, `toJSON`, symbol keys, prototype keys or arbitrary retained objects are evaluated. Check row/count/node/aggregate budgets incrementally, before whole-state allocation. Same key ID with different secret must reject.

Restore MUST validate caller-supplied limits with proxy-safe own-data descriptor checks BEFORE constructing CodexAdapter. The existing constructor spreads limits and would otherwise execute a getter or proxy trap. Accept only a plain/null-prototype object with a subset of the exact nine limit names and valid current integer values, build a fresh plain effective-limit copy, then pass that safe copy to construction. Missing/undefined argument preserves defaults. Binding and export options use the same proxy-safe exact own-data preflight. Existing direct constructor/legacy ingest semantics remain unchanged; zero-hook guarantees apply to checkpoint entrypoints and the added tracker, not all legacy ingest behavior.

Maps serialize as ordered `[key,value]` arrays and sets as ordered arrays. Preserve insertion order rather than sorting. Use owned copies on decode, freeze safe nested projections like original creation, and retain mutable private execution/source state only in the new adapter. Rejects and export unavailability leave source snapshot, retained state, counters and future ingest unchanged. No diagnostic should include original token, source path or exception text.

## Usage and provenance invariants

Ordinary native terminal records for currently verified versions 0.153.4, 0.157.0, 0.159.0 and 0.159.2 can legitimately retain `source_terminal`, `openai_responses` and eligible response increments. Unverified versions/event_msg representations retain unknown mapping/finality as existing code dictates. Fork/owner mismatch stays ambiguous and provisional. State restoration preserves that evidence; it does not promote newly observed shapes or versions. NativeUsageVerified is retained source evidence, not re-derived from a nullable later metadata projection.

Historical rows preserve origin at their observation time. A later ambiguous metadata declaration does not retroactively downgrade an earlier eligible ordinary terminal response; restore must not require every source_terminal row to have a currently nonambiguous source. Conversely, later verified metadata does not upgrade earlier unknown rows. Time-local evidence and current source flags are not interchangeable.

`response_usage` keeps response_increment; `turn_snapshot` keeps turn_cumulative; `thread_snapshot`/`token_count_total` keep thread_cumulative; `token_count_last` keeps unverified_snapshot. All nonresponse observations have unknown finality and snapshot_only selection except existing invalid/conflicted states. Trusted final/partial values and trusted ordering entries reject, including inside observedUsage. `toolEventId=null`, `phase=unknown`; response/turn IDs may be null where current diagnostics allow them.

Counts are exactly input/output/cachedInput/cacheWriteInput/reasoningOutput/total, with nonnegative safe integers or null. Preserve partial/invalid counts rather than demand all components. Mapping unknown requires total null and does not impose unverified cache/reasoning containment. For known mapping, validate current surviving numeric relationships but do not reconstruct a removed invalid component. Verified cache/read/write are already inside input; reasoning is inside output; when valid total is present it equals input+output. Never synthesize omitted total or unknown components. Zero retains zero_or_source_default limitation where existing code emitted it.

Ordinary changed values for the same response ID conflict even with increasing timestamps: no trusted source ordering exists to authorize partial6->final10 overwrite. Same final replay preserves one canonical usage row and distinct bounded source observations. Existing native-final evidence can remain in a conflicted row with counts null. Do not impose eligible iff countStatus complete: optional missing cache components can still leave an eligible partial-count response.

`lastSnapshots` is required for continuity of USAGE_RESET and REORDERED_RECORD. It retains the most recent accepted verified cumulative count point per existing keyed series and its nullable timestamp. Do not sum points, subtract adjacent points into inferred response use or let token_count_last affect cumulative reset state. Earlier timestamps warn without replacing the series; null timestamp resets the current comparison boundary as current code does. A response arriving after restore must see the same conflict and snapshot-series history as uninterrupted parsing.
